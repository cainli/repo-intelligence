## 0. 一页结论:分栈替代判定

| 技术栈 | 可替代性 | 依据 |
|---|---|---|
| **Java + MyBatis** | ✅ **今天即可替代** | v0.1.36 报告 RI 已胜(7.4 vs 6.6);v0.1.37 把 cb 仅剩的两个单点优势(throws 边、聚类自动标注)与检索短板(中文 embedding)全部补齐。cb 剩余优势(Rust/多语言)在目标栈内不生效。表链路/HTTP 全路径/歧义拒边为 RI 独有 |
| **Vue(SFC)** | ✅ **RI 反超(cb 为零)** | cb 对 .vue SFC **零语义提取**(Function=0、Route=0);RI 有 vue_page 102 + http_client_call 193(结构化 method+URL+evidence)。但双方都无组件引用链与前端路由 |
| **TS(.ts)** | ✅ **v0.1.38 起可替代**(P0 已实施) | v0.1.38 落地 TS 符号层:plus-ui 实测 function 1202 / interface 143 / type_alias 43 / enum 5,含 signature/return_type/exported metadata;跨文件 vue_page→function calls 490 条 + 文件内 calls 518 条;同名歧义 A+ 拒边(314 条记 `metadata.ambiguous_resolution` 候选清单)。验收用例 `listUser`:实体带 `AxiosPromise<PageResult<UserVO>>` 返回类型,被 UserSelect 组件与 user 管理页两个 SFC 引用可查。原缺口描述(下方保留)已被本次实施消解:~~cb 提取完整 TS 符号表;RI 只提顶层 frontend_field~~ |

**总判定**:在 vue/ts/java/mybatis 技术栈下,**RI 替代 cb 的条件 v0.1.38 起已闭环**——唯一结构性缺口
TS 函数/类型符号层(P0)已于 v0.1.38 实施(见 §0 TS 行与 §4)。cb 在该栈内已无不可替代能力;
剩余 gap(§4 P1/P2)是增强项,不构成替代障碍。

## 1. vue/ts 专项实测(plus-ui 同题对测)

### V1 "用户管理相关 HTTP 请求有哪些"

- **RI**:两个库各 1 条 SQL——前端 `http_client_call` 12 条 `GET/POST/PUT/DELETE /system/user/*`
  (含调用位置 evidence:src/api/system/user/index.ts),后端 `http_endpoint` 全路径
  (`GET /system/user/list` 等 243 个端点中的 user 子集)。URL 字符串跨库直接对上,**全链可 JOIN**
  - 注意:RI endpoint 的 name 带 method 前缀(`GET /system/user/list`),前缀匹配要
    `LIKE '%/system/user%'` 而非 `LIKE '/system/user%'`(本次实测踩坑,记入 CLAUDE.md)
- **cb**:仅 `src/api/system/user/index.ts` 的函数符号(listUser,signature/return_type 齐全,
  质量好);**URL 是函数体内字符串,无结构化实体**;后端 Route 不拼类前缀(v0.1.36 已证)。
  链路不可表达

### V2 cb 对 plus-ui 索引的实际构成(1414 节点)

- .ts 符号:Function/Interface/Variable/Enum/Type/Class(签名与返回类型质量好,如
  `listUser(query: UserQuery): AxiosPromise<PageResult<UserVO>>`)
- **.vue SFC:`file_pattern=*.vue` 的 Function = 0**;Route = 0(vue-router 路由配置未提)
- api 层函数 in_degree/out_degree **全 0**——调用方全在 .vue 里而 cb 不解析 SFC,
  **前端图退化为孤立的 .ts 符号表,无任何前端调用链**
- 默认排除 `src/views/tool/gen`、`src/api/tool/gen` 等 7 目录(代码生成页被跳过,RI 全量扫描)

### V3 RI 对 plus-ui 的实际构成(5942 实体 / 6922 边)

| kind | 数量 | 说明 |
|---|---|---|
| frontend_field | 1904 | .ts 顶层声明(变量粒度,**非函数/类型符号**) |
| vue_page | 102 | 每个 .vue 一个文件级占位实体(metadata 为空:无路由/组件名) |
| http_client_call | 193 | 结构化 method+path+evidence(confidence 0.9,对象形态 `request({url,method})` 已识别) |
| file / package | 250 / 46 | 文件与 package.json 依赖 |
| 边:contains 2200 / mapped_from 1230 / depends_on 45 | | mapped_from 为 frontend_field **同名跨文件关联**(疑似 import 解析的弱近似,质量待评估) |

**结构对比一句话:cb 有 TS 符号深度、无 Vue;RI 有 Vue 文件级与 HTTP 结构、无 TS 符号深度。
两侧在 vue/ts 栈上是互补缺口,不是覆盖差异。**

### V4 双方共同缺口(vue/ts 栈)

- 组件 import→使用边(`import UserForm from './UserForm.vue'`)
- composable/函数调用边(SFC `<script setup>` 内部与跨文件)
- 前端路由实体(vue-router `routes` 配置)
- 页面→api 函数→后端 endpoint 的自动链(RI 现状:双库 URL 人工 SQL JOIN)

## 3. cb 侧本次新实证的缺陷(对"替代"决策有利)

1. `labels(n)[0]` 聚合静默失效**再现**(plus-ui 新索引同样返回原样 1414 行,无防护)
2. `UNION ALL` 语法不支持(expected token type 85)
3. .vue SFC 零提取 + Route 零提取(见 V2)——cb 的 vue 能力宣传不成立
4. 默认排除目录吞掉 gen 模块,agent 无感知

## 4. 替代路线(gap 清单,按性价比)

1. **P0 TS 函数/类型提取**——**✅ v0.1.38 已实施**:frontend.rs 行锚定正则(prettier 保证声明首行)

   文件内词法包围 calls 边(Inferred 0.6),vue_page 带 `metadata.call_sites`,resolve 层全图唯一名

   ruoyi 回归 790 文件 unchanged 零影响。

2. **P1 vue_page 增强 + 路由**:vue_page 补 metadata(路由 path/组件名);解析 vue-router
