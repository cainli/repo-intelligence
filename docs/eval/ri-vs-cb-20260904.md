## 3. 端到端四栈链路(RI 全通;cb 三处结构性断裂)

同一问题"用户改密码的完整链路":

```
[plus-ui]  route /user/profile ──renders──▶ src/views/system/user/profile/index.vue
           页面 ──calls──▶ getUserProfile / updatePwd 等 api 函数
                     ──▶ http_client_call PUT /system/user/profile/updatePwd
           —— http-join 跨库对齐:193 调用 → 95 精确匹配(含本端点)——
[ruoyi]    http_endpoint PUT /system/user/profile/updatePwd
           ──exposes──▶ SysProfileController#updatePwd
           ──calls──▶ resetUserPwd / selectUserById(SysUserServiceImpl)
           ──▶ selectRolesByUserId(数据权限)──lambdaJoin──▶ table sys_role   ← 5 跳递归到表
```

- 前段与 JOIN 验收 SQL 见 §5;后段为单条 `WITH RECURSIVE`(inbound exposes + outbound
  calls/injects/declares/superclass_of/implements/binds_to_statement/reads_table)
- **cb 侧同一链路不可表达**(三处断裂):.vue SFC Function=0(9/2 实测)、Route=0(本轮复测
  `MATCH (n:Route)` → 0)、Table=0(9/3 实测)。链路是 RI 对 cb 的**结构性独有**,不是程度差距

## 4. 本轮新发现

### RI 侧(2 项 P2,不构成替代障碍)

1. **裸 Mapping 注解不产 http_endpoint**:类级 `@RequestMapping("/system/user/profile")` +
   方法级 `@GetMapping`(无路径)组合(SysProfileController:42/61)未提取端点;带路径的
   `@PutMapping("/updatePwd")` 正常。影响面:ruoyi 约 **23 个方法**(占 243 端点 ~9.5%)。
   修法:类级 path 前缀拼接;这也解释部分 http-join unmatched
2. **impact CLI 输出无紧凑档**:27,843 B/次(MCP trace/query 已有紧凑视图,CLI 未复用)。
   search/semantic-search/hotspots 均 ≤2.1 KB,唯独 impact 超标 13 倍

### cb 侧(对替代决策有利)

3. **Java 复杂度分析近乎不产出**:cx>1 仅 12 个方法(且集中在 enum check 方法,tld 全 0);
   full 模式重索引对照后维持——不是 moderate 模式的锅。RI 同仓库 916/395 全量覆盖
4. **ORDER BY 属性引用静默不排序**(§2 注记),agent 按 `ORDER BY f.prop DESC` 写("文档推荐写法")
   会拿到未排序的任意行,热点类查询结果不可信且无报错

```bash
  impact --entity SysUserServiceImpl | wc -c                                                                  # 27843(gap)
# 端到端后段递归到表
sqlite3 "$R" "WITH RECURSIVE reach(id) AS (SELECT id FROM entity WHERE kind='http_endpoint' AND name='PUT /system/user/profile/updatePwd' UNION SELECT e.source_id FROM edge e JOIN reach r ON e.target_id=r.id WHERE e.kind='exposes' UNION SELECT e.target_id FROM edge e JOIN reach r ON e.source_id=r.id WHERE e.kind IN ('calls','injects','declares','superclass_of','implements','binds_to_statement','reads_table')) SELECT DISTINCT t.kind,t.name FROM reach r JOIN entity t ON t.id=r.id WHERE t.kind='table';"
# → sys_role(exposes 是 method→endpoint 方向,首跳必须 inbound)
```

## 6. 结论

四轮评测(8/28、9/2、9/3、本轮)结论一致且证据逐轮加强:**vue/ts/java/mybatis 技术栈下 RI 可替代 cb,
且自 v0.1.39 起端到端全链路(route→页面→api→endpoint→Service→Mapper→表)为 RI 独有实测能力**。
cb 在目标栈内的剩余项只有检索失控(中文 62KB)、.vue/Route/Table 三处为零、复杂度近空——均已在四轮中实测固定。
本轮新增 RI P2 两项(裸 Mapping 端点、impact 紧凑档)为后续增强输入;cb 的 Rust/多语言/多库管理优势
在目标栈外,不影响替代判定。
